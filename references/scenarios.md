# 场景 SOP（五类场景的执行细则）

执行顺序：先读 SKILL.md 的"已验证快速路径"与"故障速查表"，再按本文件对应场景执行。所有场景共享 SKILL.md 的"安全边界"。

## 确认级别（两级）

- **L0 直接执行**：内容用户已明确给定、目标会话用户已明确指定，且属于"发给自己"类（文件传输助手、用户自用小群）或用户在指令中已说"直接发"。
- **L1 先确认再执行**：内容或目标群存在自由裁量空间，或面向同事/客户/工作群。流程：整理好待发送内容 → 向用户展示（文字预览）→ 用户确认 → 执行发送 → 回报确认结果。用户说"你说了算/不用确认"时降级为 L0，但内容仍以整理稿为准，不自由发挥。

## 场景 1：会议纪要 / 日报 / 周报发群

1. 内容来源：用户提供材料或指定引用的文件/会话记录；由本 agent 整理成定稿。
2. 整理完成后走 **L1**：展示定稿全文预览 → 用户确认。
3. 定位目标群（快速路径第 3 步），确认窗口标题/summary 与目标群名一致后再进入。
4. 长文本：直接一次 type_text 粘贴整段；若内容含多段，一次粘贴完成，不拆多条。
5. 发送后走快速路径第 7 步确认，回报"已发送到 <群名>"。

## 场景 2：文件 / 图片 / 报告转发

1. 目标文件必须是已存在的本地路径或已生成的产物；发送前用 Bash 确认文件存在与大小。
2. 走 **L1**（发给自己/文件传输助手可 L0）。
3. 定位会话后，让 advisor 决策如何打开"发送文件"入口（微信输入框附近 + 号 → 文件）；advisor 若建议走系统文件选择对话框，在对话框中用 `press_key(["cmd","shift","g"])`（前往文件夹）粘贴路径回车选中，避免逐级浏览。
4. 发送后确认：聊天记录中出现文件卡片且文件名正确。
5. 只发用户指定的文件；不顺带发其他文件、不发压缩包除非用户要求。
6. ⚠️ 未验证项：文件选择对话框路径因微信版本而异，首次执行时按 advisor 实时决策，失败 2 次即报告。

## 场景 3：定时提醒

1. 提醒方式 = automation_update 创建一次性/循环自动化，prompt 中写明：目标会话（如"文件传输助手"或指定小群）、提醒文案全文、以及"按 wechat-desktop-automation skill 的快速路径发送"。
2. 提醒文案以"人话"为准（用户已定稿则原样使用；未定稿则生成后 L1 确认一次再固定进 automation）。
3. 发给自己/文件传输助手的定时提醒 = **L0**；发到含他人的群 = **L1**（创建 automation 前向用户确认一次）。
4. automation prompt 必须自包含：不依赖当次会话上下文，写清会话名、文案、确认要求。

## 场景 4：群消息摘要（只读）

1. 前提：目标群已在微信窗口可见（当前打开的会话）。若目标群未打开，先定位进入（允许），之后不再滚动深挖。
2. **只读取当前屏幕可见内容**：对当前截图窗口做摘要； advisor 返回的 summary 与截图中的消息为唯一信息源。
3. 禁止：滚动翻阅大段历史、访问任何外部接口、读取数据库/缓存。
4. 输出：按"谁说了什么 + 待办/提及你的点"结构化摘要，注明"仅基于当前屏幕可见消息"。
5. 只读操作 = **L0**，无需确认。

## 场景 5：多群同步通知

1. 同一条通知，多个群，**逐群发送、逐次确认**：每发送一个群前，向用户展示"即将发送到 <群名>：<内容>"并获得确认后再执行该群。
2. 每个群发送后单独回报确认结果，再进入下一个群。
3. 任一群发送失败 → 记录失败群名并继续询问是否继续剩余群；不自动重试超过 1 次。
4. 不做批量无人监督的循环；同一通知最多一次全量发送，不做轮播/重复提醒。

## 通用停止条件（所有场景）

- 微信要求重新登录 / 扫码 / 账号异常 → 立即停止并报告。
- 找不到目标会话（搜索一次后仍无）→ 停止并报告，不猜相似名。
- 同一动作连续失败 2 次 → 停止，如实报告卡点。
- 用户中途叫停 → 立即停止，未发送的内容原样保留待确认。
